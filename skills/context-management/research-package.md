# Пакет проработки

Где каталог лежит — `layout.md`; здесь — что в нём заводится и как устроен
`README.md`.

Проработка — каталог `research/` внутри пакета задачи: файлов в ней бывает
несколько, и пакет от этого не делится. У каждого файла каталога один заголовок
первого уровня.

Каталог появляется вместе с проработкой. В нём обязателен `README.md`:
центральный файл, с которого начинают чтение, — состояние и карта. Остальные
файлы агент заводит под особенности задачи; каждый владеет своим куском и не
пересказывает `README.md`.

## Что в README

Разделы идут в этом порядке.

1. **Шапка** — метка задачи, задача одной строкой, ветка. Ни даты создания, ни
   истории правок: это улика, её место в файлах разбора.
2. **Задача** — вопросы, на которые отвечает проработка, своими словами; у
   каждого указатель на файл с ответом или пометка «не начато». Ссылки на файл
   постановки нет: он может исчезнуть.
3. **Состояние** — что решено и записано в носитель, с указателем на носитель;
   что открыто, с указателем на файл, где разбирается; что не начато. Решённое,
   но не записанное в носитель, — открыто.
4. **Файлы** — таблица: файл, чем владеет, когда открыть. Каждый файл каталога
   назван здесь; файл без строки — находка. Строка `notes.md` стоит всегда, с
   пометкой «может отсутствовать»: файла может не быть, строка остаётся.

Чего в README нет: пересказа содержимого файлов — одна строка владения, а не
вывод; истории правок; отдельного раздела «статус» — состояние и есть статус.

README не пополняется разделами. Новая порция разбора — новый файл каталога и
строка в таблице; в README меняются только состояние и карта. Файл, выросший
разделами, перестаёт быть входом и становится журналом.

Образец ниже необязателен: норма — список выше, образец показывает, как она
выглядит на письме.

```markdown
# Проработка задачи `<метка>`

**Метка:** `<метка>`. **Задача:** «<одна строка>».
**Ветка:** `<ветка>`.

Этот `README.md` — вход в проработку: он держит состояние и называет остальные
файлы. Ни одно утверждение в каталоге не является принятым решением, пока не
помечено строкой «**Решено:** …».

## Задача

1. <вопрос своими словами> — `<файл с ответом>`
2. <вопрос своими словами> — не начато

## Состояние

**Решено и записано в носители:**

1. <что решено> — <носитель>, раздел «…»

**Открыто:**

- <что открыто> — `<файл>`

**Не начато:** вопросы <номера>.

## Файлы

| Файл | Чем владеет | Когда открыть |
|---|---|---|
| `<файл>` | <вид знания> | <момент, когда он нужен> |
| `notes.md` — может отсутствовать | заметки человека по задаче | нужно понять, что человек имел в виду |
```

## Файл человека

`docs/specs/features/<feat>/research/notes.md` — необязательный файл человека:
агент его читает, но не создаёт, не правит и не требует. Постановка оттуда
переносится в проработку своими словами; в «Задаче» и «Состоянии» указателей на
него нет, потому что человек может удалить файл в любой момент. Назван он только
постоянной строкой таблицы. Задачи, названные лишь в нём, проработке неизвестны.
