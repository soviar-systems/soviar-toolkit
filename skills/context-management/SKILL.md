# Контекст: где что живёт

Процесс проверки — отдельный скилл `context-guard`, он берёт нормы отсюда и не
держит свою копию.

## Атомарность владения

Один файл владеет одним видом знания. Нормы и процесс — разные виды: нормы читает
автор, процесс исполняет гейт.

Указатель называет роль или имя. Внутри пакета скилла — файл (`layout.md`), извне
— имя скилла (`context-guard`), но не путь вроде `../skills/...`: путь ломается
при переносе, имя — нет.

Второй потребитель — повод вынести. Пока читатель один, копия дешевле указателя.

## Проверяют то, что отправляют

Проверяемый объект — тот самый, который уйдёт в коммит. Между проверкой и
отправкой объект меняться не должен.

- после правок — снова проверка, а не «правки мелкие»;
- «посмотрел файл» без указания версии — не проверка: у файла две версии, из
  индекса и с диска;
- в git читать `git show :<путь>`, а не `cat`: проверяется индекс.

## Раскладка

Какой файл чем владеет и что считается отклонением — `layout.md` в этом же
пакете.

## Первый запуск в проекте, где раскладки ещё нет

Скилл не ждёт, что конституция уже написана, и не пишет её за команду.
Развёртывание — две ступени, и порядок обязателен:

1. **Раскладка без содержания.** Создать каталоги из `layout.md` и пустые
   документы. `roadmap.md` — единственный, который нельзя оставить пустым: на
   него опирается проверка существования путей. Он начинается со списка работ.
2. **Первый коммит — после первого содержательного прогона.** Скелет наполняется
   и проверяется целиком, одним коммитом. Пустой скелет не коммитится вовсе:
   правило «коммит с документом не готов, пока его не проверил страж» исключений
   не знает.

Старую раскладку (`notes/`, всё в `README.md`) не удалять за один шаг: сначала
завести новые дома, потом переносить по одному, затем убрать старое. Пока перенос
не закончен, старый каталог остаётся находкой из `layout.md` — принятой, но
находкой.
