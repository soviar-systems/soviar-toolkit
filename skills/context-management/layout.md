# Раскладка носителей контекста

Одинакова во всех проектах команды. Отклонение — находка, даже если сам носитель
хорош.

| Путь | Владеет |
|---|---|
| `AGENTS.md` | правила, действующие всегда, и индекс носителей контекста |
| `README.md` | что за проект и как начать — для человека |
| `docs/constitution/mission.md` | зачем проект и что считается успехом |
| `docs/constitution/tech-stack.md` | язык, запуск, раскладка модуля |
| `docs/constitution/roadmap.md` | что делается и что дальше — включая пути, которых ещё нет |
| `docs/GLOSSARY.md` | термины, которыми говорят человек и агенты |
| `docs/testing.md` | как писать и запускать тесты |
| `docs/specs/features/<feat>/` | материалы одной задачи: спецификация, план |
| `docs/review/` | отчёты выверки — улики, не норма |
| `misc/` | временные файлы на разбор: удалить или найти дом |
| `skills/<name>/` | как выполнять рабочий процесс |

Других мест для них не заводить. Второй каталог конституции, второй каталог
спецификаций, папка с отчётами рядом с задачей — одна норма в двух копиях.
Носителя контекста в `docs/` вне таблицы не бывает: файл в `docs/`, которого нет
в этой таблице, — находка. Второй каталог носителей контекста в корне (`notes/`,
`doc/`, `документация/`) — та же находка: имя может отличаться, роль та же.
Перенос, объявленный в `roadmap.md` с названным концом, делает находку временной,
но не законной.
Новый вид носителя контекста — повод добавить строку в таблицу; `roadmap.md` её не
заменяет.
Что такое носитель контекста и чем он не является — `docs/GLOSSARY.md`; эта
раскладка отвечает только за то, где он живёт.
Временный файл живёт в `misc/`; принять его как носитель контекста или удалить
решает `roadmap.md`, а не эта раскладка.

`AGENTS.md` грузится в каждую сессию, остальное — по необходимости: разница в
цене, а не в важности.
