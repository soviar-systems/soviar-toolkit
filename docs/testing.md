# Тесты

Заглушки записаны в верхнем регистре. Вместо `AREA`, `UNIT` и `MODULE`
подставляются реальные имена проверяемого кода.

## Команды

```bash
# поставить зависимости
uv sync

# все тесты репозитория
uv run pytest tools -q

# один юнит
uv run pytest AREA/UNIT/tests -q

# один тест
uv run pytest AREA/UNIT/tests/test_MODULE.py::TestThing -q

# покрытие одного юнита
uv run pytest AREA/UNIT/tests --cov=AREA.UNIT.MODULE --cov-report=term-missing -q
```

`tools` — корень всех юнитов: `pytest` обходит его рекурсивно, перечислять
отдельные области не нужно.

## Раскладка

Каждый проверяемый юнит — пакет, который владеет своими тестами:

```text
AREA/
└── UNIT/
    ├── __init__.py          # реэкспорт публичных имён
    ├── MODULE.py
    └── tests/
        └── test_MODULE.py
```

Юнит `widget` в `tools` — это `tools/widget/`, тесты в `tools/widget/tests/`.

## Правила

- Каталоги и файлы — с подчёркиваниями. Дефисы в путях импорта недопустимы.
- Импорт по полному имени от корня репозитория:
  `from AREA.UNIT import public_name`.
- Каждое публичное имя реэкспортируется из `UNIT/__init__.py`. Тесты
  импортируют пакет, а не файл модуля.
- `AREA/__init__.py` и `UNIT/tests/__init__.py` не создаём: `AREA` — неявный
  namespace-пакет, каталогу тестов маркер не нужен.
- В `pyproject.toml` остаётся `pythonpath = ["."]`. Путей по юнитам и
  `conftest.py` для починки импортов не добавляем.
- В `pyproject.toml` остаётся `addopts = ["--import-mode=importlib"]`. Без него
  два юнита с одноимёнными файлами тестов падают на сборке с
  `import file mismatch`.
- Тесты живут в том юните, который проверяют. В общий `tests/` их не выносим.
- Имена тестов — `test_<behaviour>`; класс — только когда случаи делят
  состояние.
- Новый юнит приходит вместе со своими тестами в том же коммите.
- Путь к тестам передаём всегда. Голый `pytest` не запускаем.
