# Бэклог: каталог отдельных файлов

Предложено человеком 2026-11-18, «на анализ»: вести бэклог отдельной директорией,
где каждая предложенная задача — свой файл с отметкой `date+time` в имени, а не
один общий список. Тогда агент берёт задачу из отдельного файла и удаляет взятый
файл, а не переписывает общий. Решения нет.

## Зачем это может быть нужно

1. Общий список — точка столкновения: две правки одного файла переписывают друг
   друга, и разрешать приходится вручную.
2. Взятая задача исчезает удалением файла, а не правкой строки; история остаётся
   в git, а список — короткий.
3. Файл задачи читается целиком, без соседних задач: у предложения есть место
   для обоснования, а не одна строка.

## Что надо проверить

- бэклог как носитель контекста: нужна строка в `layout.md` или это временные
  файлы `misc/`, пока задача не принята;
- имя `date+time`: формат, часовой пояс, что при совпадении минуты;
- кто заводит файл: человек или агент;
- нужен ли индекс каталога: иначе не видно, что в нём лежит;
- что происходит с отклонённой задачей: удаляется или становится уликой;
- когда удаляется взятый файл: в коммите, который заводит пакет задачи, или сразу;
- чем бэклог отличается от `roadmap.md`: «что дальше» уже там, и второй список
  того же — находка по критерию 2, если не разделить роли.
