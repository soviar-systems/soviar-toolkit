# Tech stack — `soviar-toolkit`

> Только уникальное для этого репозитория: чем здесь пишут и как это запускают.
> Общие практики команды — в скиллах.

## Языки

Основной язык — **Python**: почти вся работа модулей — разбор и запись JSON и
раскладка файлов.

Bash допускается для тонкой обвязки — там, где работа и состоит в вызове
команд. Логику на bash не пишем: её нельзя нормально покрыть тестами.

## Имя файла совпадает с языком

Расширение скрипта — это язык, на котором он написан. Файлов без расширения
нет: иначе непонятно, чем запускать и что ревьюить.

## Запуск

Вход проекта — `bootstrap.py` в корне. Требования к нему:

- исполняемый, бит `chmod +x` хранится в git; шебанг
  `#!/usr/bin/env python3`, запуск `./bootstrap.py --all`.
- Только стандартная библиотека: точка входа работает системным
  интерпретатором, а не окружением проекта. Синтаксис и API — не новее
  `requires-python`.
- `bootstrap.py` — тонкий вход: реестр инструментов и разбор флагов. Установка
  конкретного инструмента живёт в `tools/<name>/<name>.py`. Bash в установке не
  участвует: снаружи виден только код выхода, а разбор флагов и слияние
  `settings.json` так не проверить.

## Предпосылки

Для запуска нужен системный `python3` не ниже `requires-python`.

`uv` — инструмент разработки, а не запуска: `dependencies = []` в
`pyproject.toml`, а `pytest` и `pytest-cov` лежат в группе `dev`. Поэтому
`uv sync` и активированный venv нужны для тестов, но не для `./bootstrap.py`.

Интерпретатор для тестов задаёт `.python-version`; значение живёт в нём, а не в
этой прозе — продублированное число расходится с файлом. `requires-python` —
нижняя граница, до которой проект обещает работать; она выбрана по версии
Python в текущем Debian stable.

Отдельно `uv` бывает нужен в рантайме установленным инструментам. Такой
инструмент объявляет это сам, и проверку делает его установщик, а не
`bootstrap.py`: MCP-сервер `ollama-search` запускается через `uv run --script`.
Если `uv` не найден, сообщение называет команду установки для `dnf` или `apt` и
дальнейший `uv sync`.

## Тесты

`pytest`. Раскладка тестов, команды запуска и настройка импорта — в
`docs/testing.md`.

## Раскладка модуля

```text
tools/<name>/
├── __init__.py     # пакет, импортируется по имени
├── <name>.py       # код: установка и логика модуля
├── payload/        # всё, что модуль ставит: конфиги, хуки, исполняемые файлы
└── tests/          # pytest
```

- `payload/` — единственное место артефактов. Установщик берёт файлы только
  оттуда; копировать их или сливать с существующими — решает установщик, но
  искать их где-то ещё ему не нужно.
- В корне модуля только код, `payload/` и тесты. Новых каталогов в корне не
  появляется: иначе следующий модуль назовёт свои данные иначе и правило
  перестанет работать.
