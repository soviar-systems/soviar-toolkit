# Миссия — `soviar-toolkit`

## Ядро

`soviar-toolkit` создан для централизованной разработки инструментов и
централизованного управления процессами ИИ-нативной команды. Правила, по которым
работают агенты и люди, живут здесь, в одном месте, и меняются здесь же.

Свой собственный контекст — не главный результат, а первый полигон: на нём
инструмент проверяется прежде, чем уехать в чужой проект.

Это **лаборатория**, а не готовый набор утилит. Здесь инструменты
разрабатываются, проверяются тестами и доводятся до состояния, в котором их
можно доставить на любую машину разработчика **одной командой**:

```sh
./bootstrap.py --all
```

Каждый инструмент проходит путь спецификация → реализация → валидация и остаётся
проверяемым после каждого изменения.

**Раскладка документов, критерии проверки и страж перед коммитом — такой же
продукт, как утилиты.** Знание, привязанное к этому дереву, — дефект.

## Аудитория

| Кто | Что получает |
|---|---|
| Инженер soviar | рабочее окружение, одинаковое у всех, ставится одной командой |
| Новый инженер | продуктивность в первый день, без «спроси у Васи, как у тебя настроено» |
| Агент планирования — Qwen Code | одинаковые правила, хуки и MCP-серверы; разрабатывает контекст и спецификации, принимает результат |
| Агент исполнения — pi | работает по готовой спецификации в контейнере, с полными правами на правку |
| Ревьюер | изменения, обозримые человеком: маленькие фазы, тесты, спецификации |

## Что считается успехом

1. **Одна команда доставляет всё.** На чистой машине `bootstrap.py` ставит
   выбранные инструменты без ручных шагов; повторный запуск ничего не меняет.
2. **Командные правила агента одинаковы у всех.** То, что задаёт поведение
   инструмента — `mcpServers`, `hooks`, `tools` — не живёт только в личной
   настройке одного инженера: оно приходит из этого репозитория. Личные
   предпочтения остаются локальными.
3. **Изменение инструмента проверяемо.** Тесты модуля лежат внутри модуля и
   ревьюятся вместе с ним, а не отдельным деревом.
4. **Изменение обозримо человеку.** Один инструмент — одно изменение, которое
   ревьюер читает за один проход.
5. **Один файл работает у всех.** Fedora и Debian, любой пользователь:
   никаких абсолютных домашних путей в артефактах репозитория.

## Границы: три плоскости, зависимость в одну сторону

| Плоскость | Репозиторий | Что там |
|---|---|---|
| Практики и инструменты инженера | `soviar-toolkit` (здесь) | скиллы, конфигурация агентов, утилиты, `bootstrap.py` |
| Инфраструктура | `soviar-infra` | серверы, podman, `ufw`, SSH, тома |
| Личное окружение | личные скрипты | то, что не должно навязываться команде |

Правило: если инструмент настраивает **ноутбук инженера** — он здесь. Если
**сервер** — в `soviar-infra`. Если это **личное предпочтение** — в личных
скриптах, и в командный репозиторий оно не попадает.

Личные скрипты вызывают установщик из этого репозитория; обратной зависимости
нет.

## Что здесь не делаем

- Серверную конфигурацию и инфраструктурные скрипты — это `soviar-infra`.
- Личные настройки (тема, выбор модели, история сессий) — они остаются у
  инженера.
- Секреты в любом виде. Только имена переменных окружения, значения — в
  окружении машины.
